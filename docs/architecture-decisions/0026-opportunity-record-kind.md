# ADR-0026: Opportunity is a Project Intelligence record kind

**Status:** Accepted (Phase 4 proposal §4 and §15.1–15.2; approved 2026-09-30)

## Context

Spec §6 asks for an Opportunity Register "for strategic possibilities". The Phase 3 vocabulary already has Structural Leverage (a durable structural advantage the strategic model uses), Intended Outcome (the result sought) and Recommendation (TPLCo's advised course of action). An opportunity is none of these: it is a possibility that may be lost if it is not acted on.

## Decision

- `opportunity` is a seventh Project Intelligence record kind on the element spine (ADR-0013), with the reference prefix `OPP` (ADR-0025).
- Its subtype table `opportunities` holds a category, value (1–5), feasibility (1–5), a generated attractiveness (value × feasibility, never typed in), an optional window (`window_opens_on`, `window_closes_on`), a pursuit approach and `opportunity_status` (`identified`, `evaluating`, `pursuing`, `realized`, `declined`, `lapsed`).
- Two relationship types join the vocabulary (33 in total):
  - `advances`: Opportunity → any element other than a Risk or an Opportunity. The mirror of `threatens`.
  - `pursues`: a Capability or Application object, a Decision or a Recommendation → Opportunity. The mirror of `mitigates`.
- Existing pairings extend to opportunities where they already apply (`underpins`, `constrains`, `threatens`, `affects`, `addresses`, `informs`, `has_stake_in`, `subject_to`, `conflicts_with`, `supersedes`). The rules are regenerated by migration and the TypeScript vocabulary is checked against them.

## Consequences

- Opportunities publish, version, relate and evidence exactly like every other element.
- The `element_kind` value and the `OPP` codes are permanent.
