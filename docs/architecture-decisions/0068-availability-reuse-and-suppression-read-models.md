# ADR-0068: Availability, reuse and suppression read models; Suggested interpretations and the kept register

**Status:** Accepted (Phase 7B.2 Step A; decisions approved by Kerrick 2026-10-01)

## Context

Phase 7B.2 proposal §5.2, §9, §16, §20, §21, §24 and §26; reconciliation decisions IX-13, IX-14, IX-16, IX-17 and IX-18, and principles 18, 20 and 23; Kerrick's PD-10 to PD-17.

An interpretation action should appear only where a deterministic rule says there is something to interpret, and the person should be told why (principle 23). The same question should give the same answer while nothing has changed (principle 18), and a judgment that an interpretation is not material should not be undone by the next person who opens the drawer (IX-14). Kept interpretations of the Examine kinds need a home beside the Edge that never contaminates it (IX-17). None of this may be decided in UI code, and none of it may reveal interpretations to non-holders (IX-18).

## Decision

**The activation gate is composed in two places.** The database cannot see the processing mode, the evaluated-model manifest or the provider configuration, so `composeGate` (`experience/gate.ts`, pure and unit-tested) combines the database's answers with them. An action is offered only when all hold: the mode is not `off` (and is `enabled`, or the engagement is synthetic); the viewer holds `use_architecture_intelligence`; the engagement is `proposed` or `active` and authorised for every class the kind's plan requires, under the configured provider and region; a provider and requested model are configured and the kind's current prompt lists that model as evaluated (ADR-0071, ADR-0073); the Gateway's pre-send estimate fits the per-request ceiling and the month's budget; and the deterministic availability rule holds. The Gateway re-runs its own checks on every request; the gate never grants what the Gateway would refuse. The server action that invokes re-reads the gate and the rule, so an out-of-date screen cannot invoke.

**The availability rules are the closed set (PD-10).** `private.ai_availability_rule(engagement, kind, subject)` holds one rule per action and returns whether it holds and the reason shown as "Offered because …". It reads no model output and calls nothing. The subject is passed as jsonb with the 7B.1 subject keys (`type`, `element_id`, `second_element_id`, `version_id`, `rule_key`, `fingerprint`, `link_id`, `link_type`).

| Action               | Subject                   | Holds when (all)                                                                                                                                                                                                                                                                                                                     |
| -------------------- | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Explain significance | Edge item                 | The item, matched by rule key and fingerprint, exists on the element; it is not `ambient`; and its trigger is a substantive revision or its consequence path is non-empty                                                                                                                                                            |
| Explain significance | Revision                  | The version is a `substantive_revision` (ADR-0053) whose changed paths include `statements` or `summary`                                                                                                                                                                                                                             |
| Explain significance | Impact trace              | The on-demand trace reaches at least one other element through a relationship whose propagation is not `never`                                                                                                                                                                                                                       |
| Examine tension      | Element pair (A, B)       | A and B differ and are connected by an unretired typed relationship or by A's impact trace; both latest published versions carry statements; and either a current Edge item's subject, trigger, basis or consequence path names both (PD-11), or one side's latest substantive revision is later than the other's latest publication |
| Examine bearing      | Evidence link             | The statement or element link exists on the element, the element is not retired or superseded, and the evidence source has a recorded summary (PD-12)                                                                                                                                                                                |
| Compare with intent  | Implementation Initiative | The initiative `implements` at least one published, live element, and has at least one checkpoint or a status other than `not_started`                                                                                                                                                                                               |
| Prepare              | Review                    | The Review is `scheduled` or `held` and has at least one unretired `examines` relationship                                                                                                                                                                                                                                           |

A broader or narrower rule is a reviewed migration, not a UI change.

**Availability and suppression.** `public.architecture_intelligence_availability(engagement, kind, subject)` returns `rule_holds`, `reason`, the latest kept inference of that kind on that full subject (`latest_inference_id`), its computed state, its latest judgment kind and time, and `suppressed`. Suppression is computed, never stored: the latest kept inference is `current` and its latest judgment is `not_material` or `disagree`. It is engagement-wide (PD-14): one holder's judgment suppresses re-offering for every holder, as Edge judgments do. It ends when the inference goes stale, that is, when its basis changes (IX-14). While suppressed, layer 2 shows "You judged this interpretation not material on …" (or "You disagreed with this interpretation on …") and offers **Interpret again**, which is deliberate and audited (`interpret_again = true`, ADR-0066 amendment).

**Reuse (IX-13, PD-13a).** `public.current_architecture_inference(engagement, kind, subject, prompt_version, provider_key, requested_model)` returns the kept inference to show in place of a new request only when all hold:

- it is the latest kept inference of the same kind on the same full subject (every subject column, including an Edge item's fingerprint and a revision's version);
- `architecture_inference_state` reports it `current`: every basis row re-emits with the same digest, nothing was removed, no class was withdrawn, and it is not superseded;
- its prompt version is the kind's current prompt version;
- its provider and requested model equal the configured ones;
- its resolved model equals the resolved model most recently recorded on this engagement's request audit for that provider and requested model. A change of resolved model ends reuse even when provider, requested model and prompt are unchanged: reuse never crosses resolved model identity.

The application additionally requires the inference's resolved model to be evaluated for that prompt version (`getLayer2`). Reuse calls no provider and writes no audit row; nothing leaves DSA. The drawer shows the kept inference with its generation time and **Interpret again**. Where reuse does not apply, the drawer shows the newest kept inference with its state (current, stale or superseded) beside the action. Ephemeral interpretations are never reused, and `nothing_to_add` is never a reuse key.

**Kept Review briefs (PD-7).** A kept `review_brief` is visible to every holder on the engagement. The newest kept brief on a Review supersedes earlier ones, which remain in history. Supersession compares the full subject (`private.same_inference_subject`), which corrects the 7B.1 comparison that matched on the first element only (migration `20261008000100`).

**Suggested interpretations (IX-17, PD-15).** `public.suggested_interpretations(engagement)` returns kept `tension`, `evidence_bearing` and `realization_reading` inferences that are `current` (not stale, not superseded) and whose latest judgment is none, `investigating`, or a `deferred` whose date has come. For each it returns kind, subject codes and titles (both elements of a pair), link identity, assertion, generation and keep times, the latest judgment and the subject's nearest governance date. Order is that governance date ascending (none last), then keep time, newest first: an ordering of dates, never of importance. `private.ai_element_governance_date` takes the earliest of the next scheduled Review examining the element, an open Decision's needed-by date and an unachieved checkpoint's target, each on or after today. The section sits on the Engagement Edge below every tier, with the description "Interpretations kept by architects on this engagement. Suggested, not established by DSA's rules." It is never counted, ranked, severity-styled or placed in a tier, and never appears in the overview's Development Edge section, the "Since you were away" briefing, contextual Edge panels or whole-event judgment. `explanation` and `review_brief` never appear there; a kept one shows only in its subject's drawer. `edge_items` is unchanged.

**The kept register (PD-16).** `public.kept_architecture_inferences(engagement, kind?, state?)` lists every kept inference on the engagement with kind, subject, assertion, computed state and stale reasons, latest judgment, and generation and keep times, newest kept first, filterable by kind and state. It is a section of the Architecture Intelligence page for holders, shown as an archive whatever the processing mode. The list names no requester and nothing in it counts, ranks or charts by person (principle 20); the requester appears only as provenance inside an inference's "How this was produced" disclosure.

**One inference's detail.** `public.architecture_inference_detail(engagement, inference)` returns the interpretation, subject, provenance (provider, requested and resolved model, prompt, policy and contract versions, generation and keep times, the requester's display name), computed state and stale reasons, a citation label per handle built from identities only (`private.ai_basis_label`: reference codes and versions, an Evidence title at most), and its judgments, newest first.

**Who receives what.** Every function above is `security definer`, `search_path = ''`, read-only (no DML; proven in `50_ai_experience_no_mutation`), executable by `authenticated` only, and refuses an engagement the caller cannot read (`P0002`), so a client receives nothing. `architecture_intelligence_availability`, `current_architecture_inference` and `architecture_inference_detail` refuse a non-holder (`42501`). `suggested_interpretations` and `kept_architecture_inferences` return an empty set to a non-holder, so a page can call them for any internal reader and render nothing, not even a heading.

**Large requests (IX-25, PD-17).** When the Gateway's pre-send estimate exceeds half the per-request ceiling (`isLargeRequest`), the person confirms "This is a larger request than usual. Continue?" before anything is sent. No currency or budget figure is shown to anyone for this; budget figures stay on the Architecture Intelligence page for authorisers (ADR-0066).

## Consequences

- No AI action appears without its rule holding, and each says why. Rules are identical on every surface and are tested true and false in pgTAP (`49_ai_read_models`) and Vitest (`gate.test.ts`).
- Two people asking the same question of the same unchanged records see the same kept interpretation, and nothing is sent the second time.
- A judgment of `not_material` or `disagree` holds for the whole engagement until the facts change; anyone may still ask again deliberately, and that is recorded.
- Kept Examine interpretations are visible beside the Edge to holders without ever entering the envelope, its tiers or its counts.
- Implementation notes: the revision rule accepts a change to `statements` or `summary` (the proposal said "at least one statement path"); the Edge-item rule considers only items whose subject is an element, as the `explanation` subject requires; the tension rule's "later than" compares one side's latest substantive revision with the other's latest publication (first publication or substantive revision).
